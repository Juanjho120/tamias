# Phase 9J — Reservation supply and task read-only AI tools

Phase 9J extends TAMIAS AI tool calling with backend-owned, read-only tools for reservation supplies, task lists and task items.

## Scope

This phase stays within the approved safety model:

- Read-only first.
- No free SQL generated by the AI model.
- No autonomous writes.
- Organization scope is resolved by the backend.
- Current user context remains backend-owned.
- Tool evidence is returned with system-data responses.

## Added tools

### Reservation supply tools

- `reservationSupply.search`
- `reservationSupply.byReservation`
- `reservationSupply.byProperty`
- `reservationSupply.forUpcomingReservations`
- `reservationSupply.summaryByItem`
- `reservationSupply.summaryByDateRange`
- `reservationSupply.lastUsed`
- `reservationSupply.mostUsed`
- `reservationSupply.missingForUpcomingReservations`

### Task list tools

- `taskList.search`
- `taskList.byProperty`
- `taskList.byReservation`
- `taskList.active`
- `taskList.completed`
- `taskList.pending` remains supported through the existing pending/active path
- `taskList.overdue`
- `taskList.dueToday`
- `taskList.dueThisWeek`
- `taskList.progressSummary`
- `taskList.completionSummary`

### Task item tools

- `taskItem.search`
- `taskItem.byTaskList`
- `taskItem.pending`
- `taskItem.completed`
- `taskItem.overdue`
- `taskItem.assignedSummary`
- `taskItem.prioritySummary`

`taskItem.prioritySummary` intentionally reports that the current schema does not expose priority metadata for task items. It does not invent a priority field.

## Schema notes

- Reservation supplies use `reservation_supplies` from `V21__create_reservation_supplies.sql`.
- Task lists and task items use `task_lists` and `task_items` from `V12__create_task_lists.sql`.
- The current `task_items` schema does not include a priority column.
