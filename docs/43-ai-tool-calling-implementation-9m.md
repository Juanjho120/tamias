# Phase 9M — File/Image Metadata and Dashboard Analytics

## Scope

Phase 9M expands the TAMIAS AI Assistant with read-only tools for file/image metadata and dashboard-level analytics.

This phase keeps the same safety model used in previous Tool Calling phases:

- Read-only first.
- No autonomous writes.
- No free SQL generated by the model.
- Backend-owned `organization_id` resolution.
- Backend-owned current user resolution.
- No private S3 URLs exposed by the assistant.
- Metadata only for file/image tools.

## Added tools

### File / image metadata tools

- `file.searchMetadata`
- `file.byProperty`
- `file.byMaintenance`
- `file.byDocument`
- `file.storageSummary`
- `file.orphanFileCandidates`
- `image.propertyImagesSummary`
- `image.maintenanceImagesSummary`

These tools consult metadata from:

- `documents`
- `property_images`
- `maintenance_record_images`

They intentionally do not return private S3 keys as direct URLs.

### Dashboard / analytics tools

- `dashboard.reservationSummary`
- `dashboard.maintenanceSummary`
- `dashboard.purchaseSummary`
- `dashboard.taskSummary`
- `dashboard.documentSummary`
- `dashboard.calendarEvents`
- `dashboard.alertSummary`
- `dashboard.executiveSummary`

These tools provide operational summaries that combine existing data without modifying records.

## Notes

- `file.orphanFileCandidates` is metadata-based only. It does not scan the S3 bucket directly.
- `image.*` tools only summarize metadata. Visual image analysis is intentionally out of scope for this read-only phase.
- `dashboard.calendarEvents` currently combines reservations, scheduled maintenance and task list due dates for the next 14 days.
- `dashboard.alertSummary` highlights overdue scheduled maintenance, overdue tasks, failed documents, processed documents without index evidence, and near-term check-ins.
