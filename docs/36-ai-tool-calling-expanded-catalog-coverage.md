# TAMIAS — AI Tool Calling Expanded Catalog Coverage

## Purpose

This document tracks the expanded read-only AI tool catalog for TAMIAS and separates three concepts:

1. **Designed**: the tool is part of the approved long-term catalog.
2. **Implemented**: the backend has a working read-only method and router support.
3. **UX visible**: the frontend can display the resulting tool evidence clearly.

The expanded catalog is intentionally broader than the first implementation. Tools must remain read-only unless a future phase explicitly designs safe write workflows with confirmation, audit and permissions.

## Current implementation status

As of Phase 9D, TAMIAS has a working read-only AI tool foundation with deterministic routing, backend-owned SQL and frontend tool evidence display.

## Security rules for all catalog tools

Every tool must follow these rules:

```text
- Read-only first.
- No free SQL generated by the model.
- organization_id must come from CurrentUserService.
- current user must come from CurrentUserService.
- Never accept organizationId or userId from the AI request body.
- Every query must filter by organization_id.
- Soft-deleted records must be excluded.
- Result size must be limited.
- Guest/user PII must be minimized.
- Private file URLs must not be returned unless explicitly needed and authorized.
- Admin-only tools must check ADMINISTRATOR role before returning organization-wide user/role data.
```

## Recommended implementation order

Do not implement the whole catalog in one commit. The safest order is:

```text
9G — Property and catalog read-only tools
9H — Inventory and maintenance analytics tools
9I — Scheduled maintenance, reservation and guest tools
9J — Reservation supply and task tools
9K — Purchase analytics tools
9L — Document metadata and RAG health tools
9M — File/image metadata and dashboard analytics tools
9N — Admin-only user, role and organization tools
9O — AI chat session history tools
```

## Human response quality rules

The assistant should avoid repetitive template answers. Tool responses should be specific to the question.

Examples:

```text
Question: ¿Cuál es mi nombre?
Good: Te llamas Juan Tzun.
Avoid: Tu perfil actual en TAMIAS es...
```

```text
Question: ¿Cuál es mi correo?
Good: El correo actual que estás usando es juan@example.com.
Avoid: Tu perfil actual en TAMIAS es...
```

```text
Question: ¿Qué propiedades tengo activas?
Good: Tienes 2 propiedades activas: Lake View Bungalow y Garden Cabin.
Avoid: No encontré información suficiente en documentos indexados...
```
