# 15C — Organization Switcher / Multi-Organization Navigation

## Status

Implemented with follow-up fixes.

## Goal

Allow users with access to multiple organizations to change the active organization from the UI.

The switch is validated by the backend and returns a new JWT/session with the selected organization id. TAMIAS does not trust a client-side organization override stored in localStorage or sent through a custom header.

## Backend endpoints

```http
GET /api/v1/auth/organizations
POST /api/v1/auth/switch-organization
```

## Runtime behavior

- Users with a single active organization do not see the selector.
- Users with multiple active memberships see the selector.
- `SUPER_ADMIN` users see all active, non-deleted organizations.
- Switching organization returns a new access token.
- The frontend replaces the current token/session and routes to `/dashboard`.
- If the user is already on `/dashboard`, the dashboard is forced to reinitialize so organization-scoped data is refreshed.

## Last organization selection

TAMIAS stores each user's last selected organization in `users.last_organization_id`.

On login:

- `SUPER_ADMIN` users return to their last active organization.
- Regular users return to their last organization only if their membership is still active.
- If the last organization is unavailable, TAMIAS falls back to the default active membership.

## Security

The active organization must come from the JWT generated by the backend.

Regular users can only switch to organizations where they have an active membership.

`SUPER_ADMIN` users can switch to any active, non-deleted organization and keep the `SUPER_ADMIN` role in the generated JWT.
